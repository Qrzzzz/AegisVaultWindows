# AegisVault 2.7

Release date: 2026-09-12. Product version: **2.7**; Windows assembly/PE versions: **2.7.0.0**.

## File queues

- Drop multiple files into the File page or Base64 file mode, or use the native multi-select picker. Files appear in a scrollable stack with names, full-path tooltips and individual status.
- Add files and remove waiting entries while a batch runs. The active file remains fixed; operation, password and output directory apply to the whole run.
- Process files sequentially. A failed file does not prevent later entries from running. Retry individual failures; adding more files does not repeat completed work.
- Cancel the current operation safely. Committed outputs remain available, pending entries stay queued, and the next run retries cancelled work and continues the queue. Passwords must be entered again.
- View each successful output, open its folder or copy all retained result paths. Same-name outputs are numbered; batches never overwrite existing files, even if the single-file overwrite preference is enabled.

## Backend and compatibility

`file.batch` accepts up to 256 files for AGV1 encryption/decryption or Base64 file encoding/decoding. It returns independent outcomes, aggregate progress and cancellation state. Request path metadata is bounded before writes. Existing single-file operations, AGV1 contents, text operations and settings storage remain compatible.

Desktop queue management submits each ready entry to the batch endpoint in turn, allowing pending additions and removals to take effect before the next request. External clients may submit a fixed list in one request; see [batch IPC](https://github.com/Qrzzzz/AegisVaultWindows/blob/v2.7/docs/BATCH_IPC.md).

## Download and validation

Download `AegisVault-v2.7-win64.zip` and extract the entire folder before running `AegisVault.exe`. The release also includes `AegisVault-v2.7.cdx.json` and `SHA256SUMS`. Artifacts are rebuilt from the annotated `v2.7` tag and verified by the Release workflow before publication.

Local checks passed 394 Python tests, 22 IPC scenarios, the x64 build/package audit, and native picker/queue runs in light/English and dark/Chinese. Real Explorer drag/drop, High Contrast, Narrator and the full multi-monitor/DPI matrix remain manually unverified; picker/queue automation does not establish external drag/drop acceptance. Queue state is session-only. Details are in the [acceptance record](https://github.com/Qrzzzz/AegisVaultWindows/blob/v2.7/docs/ACCEPTANCE_2.7.md).
