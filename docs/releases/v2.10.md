# AegisVault 2.10

Release date: 2026-10-14. Product version: **2.10**; Windows assembly/PE: **2.10.0.0**.

- Deeply nested AGV1 header JSON now becomes a per-file `crypto.invalid_header` error. Later valid queue files continue processing, and already committed outputs remain available (#48).
- Desktop password fields accept full passwords without silently truncating at 1024 characters. Desktop, Web and backend share a new-encryption limit of 32768 UTF-16 code units and 98304 UTF-8 bytes. Existing longer-password AGV1 envelopes remain decryptable within the existing IPC budget (#49).
- The Settings page explains automatic collision numbering for all file queues, including single-file queues. The ineffective overwrite control is removed; existing settings and the backend single-file overwrite API remain compatible (#50).
- The Web build lock updates `source-map-js` from 1.2.1 to 1.2.2 to clear [GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q); this is a build dependency advisory.

AGV1 formats, AES-256-GCM, scrypt defaults, plaintext/encoded-text budgets, atomic output publication and cancellation cleanup remain compatible.

Release artifacts: `AegisVault-v2.10-win64.zip`, `AegisVault-v2.10.cdx.json`, and `SHA256SUMS`. The tag-bound workflow rebuilds, audits, attests and verifies these assets before public publication. GitHub provenance is separate from optional Authenticode signing.
