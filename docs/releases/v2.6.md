# AegisVault 2.6

Release date: 2026-09-12.

- #23: Settings saves submit only fields changed since the draft was loaded. Another window's theme edit preserves a previously disabled recent-file history setting. Different fields merge; the last explicit save wins for the same field.
- #24: Settings recovery drops invalid Unicode history entries and resets an invalid output-directory string, while preserving valid values. Runtime settings reject invalid Unicode before writing.
- #25: Web copying and result reuse preserve the original CR, CRLF, LF, BOM, NUL and Unicode characters. Editing the input replaces the reused raw text.
- #26: AGV1 and Base64 file restoration validate output names before collision numbering. Invalid names produce a localized error before output is written; valid restores retain the selected output directory and no-overwrite behavior.
- #32: Desktop UTF-8 import consumes one initial BOM and preserves subsequent body U+FEFF characters. Strict decoding, input limits and failed-import preservation remain in place.

The AGV1 format, cryptographic parameters, settings file format and existing compatibility fields remain compatible. This release does not change runtime dependencies.

Release assets: `AegisVault-v2.6-win64.zip`, `AegisVault-v2.6.cdx.json`, and `SHA256SUMS`. Fully extract the ZIP and keep the application, backend and runtime files together.

See [acceptance evidence](../ACCEPTANCE_2.6.md). The release workflow rebuilds from the annotated tag, audits the package and verifies asset digests and provenance before publication. The build uses optional signing; provenance does not imply an Authenticode signature. Previous intermittent native COM-finalizer shutdown failures are not claimed fixed by this issue scope.
