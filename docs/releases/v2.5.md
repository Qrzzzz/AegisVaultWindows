# AegisVault 2.5 — consistent backend decoding errors

Malformed UTF-8 from a faulty backend now produces `ipc.invalid_response` instead of escaping as
`DecoderFallbackException` (#20). This includes truncated sequences at EOF. Valid non-BMP characters
split across transport reads remain intact; cancellation, bounded responses and process cleanup are unchanged.

The release retains and revalidates the 2.2 fixes for Base64 source mutation rollback (#9), malformed
settings JSON recovery (#10), and process-shared settings transactions that preserve privacy choices (#11).
These three repairs were already present in 2.4; 2.5 does not claim they are newly implemented.

AGV1, scrypt, AES-256-GCM, the settings schema, the WinUI interface, and the 2.4 text/file naming budgets
remain unchanged. No legacy decryption support is restored. The new regression concerns injected invalid
backend bytes, not a demonstrated crash in an ordinary Python-backed workflow.

Release artifacts are `AegisVault-v2.5-win64.zip`, `AegisVault-v2.5.cdx.json`, and `SHA256SUMS`.
Extract the entire ZIP and keep the backend and runtime files together. Product version is `2.5`;
Windows PE/assembly version is `2.5.0.0`. Optional signing does not imply an Authenticode signature.

See [2.5 acceptance](../ACCEPTANCE_2.5.md) for executed checks and remaining native/remote gates.

Known validation limitation: one local native run encountered a COM finalizer access violation on exit.
The same official 2.4 baseline and a full 2.5 retry exited normally. The cause remains unconfirmed;
this release does not claim to fix that intermittent shutdown anomaly.
