# AegisVault 2.8

Release date: 2026-09-12. Product version: **2.8**; Windows assembly/PE: **2.8.0.0**.

- File queues show processed/waiting counts independently of the current file's percentage and byte progress. Adding or removing pending files updates the counts without changing the current file's percentage.
- Filter failed files, queue all failures again, or clear completed entries. Filtering never changes processing order; retry preserves successful results; clearing entries leaves output files on disk. Requeued files start with the normal operation button and require passwords again for AGV1.
- Open output details on each successful queue row. File workflows no longer duplicate every output in a separate result editor; text results retain their existing editor and actions.
- Actual Explorer multi-file drops, Text/File and Base64 routing, appending during processing, duplicate suppression and file/folder rejection passed automated external drag/drop checks. Details are recorded separately from picker, view-model and backend checks in [2.8 acceptance](https://github.com/Qrzzzz/AegisVaultWindows/blob/v2.8/docs/ACCEPTANCE_2.8.md).

AGV1, sequential processing, safe cancellation, collision numbering, settings storage and bilingual controls remain compatible. Queue state is session-only; passwords are not persisted.

Download `AegisVault-v2.8-win64.zip` and extract the complete folder before running `AegisVault.exe`. The release also includes `AegisVault-v2.8.cdx.json` and `SHA256SUMS`. The Release workflow rebuilds artifacts from the annotated `v2.8` tag, verifies checksums and GitHub provenance, and audits the uploaded assets before publication.

Local verification passed 394 Python tests, 25 linked-source IPC scenarios, the x64 build/package audit, full native regression and final queue/Explorer checks in light/English and dark/Chinese. High Contrast, Narrator and the full multi-monitor/DPI matrix remain unverified. GitHub provenance is separate from optional Authenticode signing.
