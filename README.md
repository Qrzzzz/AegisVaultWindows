# AegisVault Windows 2.4

A local Windows utility for password-based text and file encryption, with separate Base64 workflows.
The current source is AegisVault 2.4. It closes bounded text roundtrips and repairs collision
naming and atomic temporary names while retaining the 2.3 backend lifecycle hardening.
It retains the **WinUI 3** interface, AGV1 format, scrypt and AES-256-GCM.
All production windows use C# and Windows App SDK. There is no legacy desktop frontend.

## Use the application

Download [AegisVault v2.4](https://github.com/Qrzzzz/AegisVaultWindows/releases/tag/v2.4), then extract the entire
`AegisVault-v2.4-win64.zip` and run `AegisVault.exe`.
Keep all runtime files and the `backend` directory together. The package includes Python, .NET and the
Windows App SDK runtime. Windows 10 2004 or newer, x64, is required; Mica is provided on supported Windows 11 systems.

Local 2.4 builds appear under `dist/AegisVault/`; the archive is `AegisVault-v2.4-win64.zip`.
See [2.4 release notes](docs/releases/v2.4.md) and [local acceptance](docs/ACCEPTANCE_2.4.md).
Earlier UI evidence remains in [2.1 UI acceptance](docs/UI_ACCEPTANCE.md).

## Workflows

- **Text:** encrypt/decrypt `AGV1.` text, confirm encryption passwords, import UTF-8 text, copy/save results or reuse them as input.
- **File:** select or drop a file, choose an output folder, encrypt/decrypt with progress and cancellation, open the result folder.
- **Base64:** encode/decode text or files. Base64 does not provide secrecy. Text decoding is strict by default and can explicitly ignore ASCII whitespace.
- **Settings:** Chinese/English, system/light/dark theme, default output folder, optional overwrite, recent-file history and clearing; drafts survive navigation until saved or discarded.

Workflow actions and feedback stay visible while the form scrolls. Result commands adapt to narrow windows,
and file results have a dedicated Copy path action. See the [2.1 review](docs/UI_REVIEW_2.1.md).

Existing configuration is read from `%LOCALAPPDATA%/AegisVault/settings.json`. AGV1 containers generated by
1.x remain compatible. Non-AGV1 formats remain unsupported; migration does not restore removed formats.
The application adds no account, network service, telemetry or cloud synchronization.

Text workflows use a shared packaged budget: plaintext is limited by UTF-8 bytes and UTF-16 code units,
encoded/AGV1 input has a separate 2 MiB limit, and the JSON Lines transport remains bounded at 16 MiB.
Every successfully generated text result can therefore be reused or imported for its reverse operation.

Base64 file operations reject detectable changes to the opened input and discard temporary output.
Settings mutations serialize across cooperating 2.2 and later processes with a five-second lock acquisition limit;
the persistent `.settings.json.lock` file is not a stale-lock marker. Invalid JSON, including integers
beyond Python's digit limit, falls back to defaults and can be repaired by saving settings.
WinUI still submits all six preferences when saving a draft, so a later explicit save from another
window can replace those fields; this is separate from server transaction protection.

## Develop and validate

Install the .NET SDK specified by `global.json` and Python 3.11–3.13, then:

```powershell
python -m venv .venv
.\scripts\install_locked_dependencies.ps1
.\scripts\run_dev.ps1
```

`run_dev.ps1` launches WinUI. `python -m aegisvault.backend` starts the JSON Lines backend, not a desktop window.
For an isolated SDK install, set `AEGISVAULT_DOTNET` to its `dotnet.exe` before running the scripts.

```powershell
.\scripts\verify_release.ps1
.\scripts\build_windows.ps1 -Clean -Zip
.\scripts\test_winui.ps1
.\scripts\test_winui.ps1 -Theme dark -Language zh-CN
```

The native UI test requires an interactive Windows desktop. It launches the actual published executable
with synthetic data, an isolated settings directory and a minimal PATH, and writes screenshots under
`build/native-evidence`. Source tests and backend smoke do not substitute for native or manual acceptance.

## Structure

```text
src/AegisVault.App/       C# WinUI Window, Pages, view models, IPC client and localized resources
src/aegisvault/core/      AGV1, cryptography, KDF and atomic file operations
src/aegisvault/services/  file naming and workflow facade
src/aegisvault/settings/  validated configuration persistence
src/aegisvault/backend/   versioned JSON Lines service
tests/                   Core fixtures, protocol, release contracts and native UI automation
scripts/                 validation, self-contained packaging, audits and release tooling
docs/                    protocol, security model, migration and measured acceptance
```

Product versions use `2.0 → 2.1 → 2.2 → 2.3 → 2.4`; PE/assembly metadata uses four components such as `2.4.0.0`.
Python and NuGet dependencies are locked, and the release SBOM covers both runtimes. A local unsigned build
is not evidence of a signed or published release.
